# CivilStock 경제 모듈 설계

> 목표: **유저가 직접 만드는 2DStock.** 유저는 시장 조성자(market maker)이자
> 시장 참여자로서 증시·실물경제·채권을 두루 컨트롤한다. 운영자는 **제재·삭제만**
> 하고, **주식·ETF 발행권은 유저에게 이양**한다. 국가 상장 주식을 ADR로 발행하는
> 등의 교차 상장 예외도 지원한다.

## 0. 2DStock과의 결정적 차이

| | 2DStock | CivilStock |
|---|---|---|
| 상장/발행 | 운영자가 종목 편성 | **유저가 발행**(주식·ETF·채권) |
| 가격 | 클라이언트 결정론 계산 | **유저 주문 흐름에서 창발**(서버 매칭) |
| 운영자 | 시장 설계자 | **제재·삭제만**(사기·조작 대응) |
| 실물경제 | 배경 시뮬 | 회사 실적·자원과 **직접 연동** |

가장 중요한 전환은 **가격 형성**이다. 유저가 시장 조성자가 되려면 가격이
결정론이어선 안 된다. 서버 권위형 매칭 엔진이 실제 매수/매도 주문을 체결하고,
그 체결에서 가격이 창발한다.

## 1. 행위자(actor)와 역할

- **유저**: 발행자(회사·ETF·채권) / 시장조성자(호가 게시·유동성 공급) /
  트레이더 / 펀드매니저 — 한 유저가 여러 역할을 겸한다.
- **국가**: 자국 통화 발행, 거래소 호스팅, 상장 규정 설정, 국채 발행. (국가는
  1인국 또는 멀티국이 운영 — §국가 설계와 연결.)
- **회사/ETF/채권**: 유저가 발행하는 상품.
- **운영자(admin)**: 제재·삭제만. 발행 게이트키핑 없음.

## 2. 상품(instrument) 분류

`src/lib/economy/types.ts`의 `SecurityType`.

1. **주식(equity)** — 유저 회사 지분. 발행자가 발행량·증자·자사주·분할·배당 통제.
2. **채권(bond)** — 국채/회사채. 원금·표면금리·만기·쿠폰주기. 발행자 파산 시 디폴트
   (전쟁 패배 국가의 국채 디폴트 등 §전쟁과 연결). 신용도는 창발.
3. **ETF(etf)** — 유저가 구성한 바스켓(주식·채권·다른 ETF·자원 편입 가능).
   생성/상환은 바스켓 대비. NAV는 구성종목 시세로 계산.
4. **ADR(adr)** — 홈 시장 상장 증권을 **다른 시장의 통화로 거래**하는 예탁증서.
   예탁기관(유저/기관)이 홈 주식을 보관하고 ADR을 발행·상환. ADR 1주 = 홈 주식
   `ratio`주. 시세는 자시장 주문 흐름에서 창발 → 홈가격×FX 대비 **차익거래**
   여지가 콘텐츠가 된다.
5. **통화(currency)** — 국가 통화(FX). 국가가 발행량 통제 → 인플레·환율.
6. **자원/재화(commodity)** — 실물경제 산출물. 회사의 투입/산출과 연동.

모든 상품은 공통 헤더(`Security`) + 종류별 detail 레코드로 구성. 매칭·정산 코어는
상품 종류에 무관하게 동작한다(어떤 상품이든 호가장 + 원장으로 거래).

## 3. 발행(issuance) — 발행권 이양의 핵심 (구현 완료: 순수 코어)

발행 ≠ 판매를 분리한다. 발행은 상품 레코드 생성 + 발행자 포지션 크레딧이고,
이후 매도·유동성 공급은 CLOB/AMM/라우터가 담당. 파일: `src/lib/economy/issuance.ts`.

- **회사 설립 → 주식 발행(IPO)**: `issueEquity`가 발행주식수·통화로 상장하고
  발행자에게 전량 크레딧. `issueSecondary`로 증자. (자사주·분할·배당은 확장.)
- **ETF 발행**: `issueEtf`로 구성종목·비중 정의. `etfNav`로 시세 기반 순자산가치,
  `createEtfShares`/`redeemEtfShares`로 바스켓↔ETF 생성·상환(포지션 원자 이동).
- **채권 발행**: `issueBond`로 원금·표면금리·만기·쿠폰주기 정의. `bondCouponPerUnit`이
  1좌·1주기 쿠폰액 계산(연율 → 틱 환산). 1차 판매는 원장 체결로.
- **옵션 발행**: `issueOption`으로 상품 생성(행사·증거금은 파생 엔진 다음 슬라이스).
- **스팸/사기 방지(발행은 자유롭되)**:
  - 국가 거래소별 **상장 규정**(최소 자본·공시 의무)을 국가 운영 유저가 설정.
  - **평판/공시**: 발행자 신뢰도, 허위공시 페널티.
  - 운영자 **제재·삭제**: 명백한 사기·조작만 사후 개입.
  - 서버 **불변식**: 발행량 보존, 음수 잔고 금지(§정산).

## 4. 가격 형성 — CLOB + AMM 병용 (확정, 구현 완료: 순수 코어)

유동성 모델은 **호가장(CLOB) + AMM 유동성 풀 병용**으로 확정(2026-08-03).
시장조성 = 호가 게시(CLOB) *또는* 풀 예치(AMM) 둘 중 하나로 할 수 있다.

- **CLOB — 가격-시간 우선 지정가 호가장.** `matchOrder`가 들어온 주문을 반대편
  호가장(best-first)과 체결하고 **메이커 가격**으로 체결가를 매긴다(테이커에 가격
  개선). 부분체결·잔량 처리. 파일: `src/lib/economy/orderBook.ts`.
- **AMM — 상수곱(x·y=k) 유동성 풀.** 유저가 풀에 유동성을 예치하면 호가장이
  비어도 언제나 즉시 매매 가능. 스왑 수수료는 LP에 귀속. `spotPrice`는 CLOB
  가격과 **동일 단위**(기초 1.0단위당 결제통화 최소단위)라 두 시장을 나란히
  비교·차익거래할 수 있다. 파일: `src/lib/economy/amm.ts`
  (`swapQuoteForBase`, `swapBaseForQuote`, `addLiquidity`, `removeLiquidity`).
- **스마트 라우터(구현 완료).** `routeBuy`/`routeSell`이 저렴/유리한 소스부터
  소진한다: AMM 현물가가 다음 CLOB 호가보다 유리하면 그 호가 수준까지 AMM에서
  담고, 그 다음 CLOB 호가를 소진 — 반복. AMM 임계 물량은 수수료 무시 추정이나
  실제 체결은 fee 포함 역스왑으로 정확해 가치 유출이 없다. 한도가(limit) 지원,
  풀 없는 순수 CLOB도 동작. 파일: `src/lib/economy/router.ts`.
  최선체결 검증: 동일 수량을 단일 소스로 채울 때보다 총비용↓/총수취↑(테스트).

## 5. 정산(settlement) — 원장과 불변식 (구현 완료: 순수 코어)

- **현금 원장**(userId→통화→잔액) + **포지션 원장**(userId→증권→수량).
- `settleFill`: 체결 한 건을 매수자↔매도자 사이에 정산. **검증 통과 시에만** 반영:
  - 매수자 현금 ≥ 결제금액(부족 시 `insufficient_cash`).
  - 매도자 포지션 ≥ 수량(공매도 금지 MVP, 부족 시 `insufficient_position`).
- 서버 권위: 실제로는 Cloud Run 서버가 이 규칙대로 **Postgres 트랜잭션**에서
  원자적으로 수행. 이 모듈은 테스트 가능한 기준 구현.
- 파일: `src/lib/economy/ledger.ts`.

## 6. 큰 수 처리와의 결합

모든 금액·수량은 `src/lib/number/exactAmount.ts` 위에서만 연산한다.

- 현금: 통화별 **정수 최소단위 문자열**(ExactAmount). float 금지.
- 가격: "증권 1.0단위당 결제통화 최소단위" 정수 문자열.
- 수량: 최대 6자리 소수(micros) 문자열.
- 결제금액 = `exactPositionValue(price, qty)` — 천문학적 국부 규모에서도 손실 없음.
- 테스트가 2^53 초과 체결 정산을 검증(`scripts/test-economy.ts`).

## 7. 실물경제·채권·ADR 연동(설계)

- **실물경제↔증시**: 회사는 자원을 투입해 재화를 생산 → 매출·실적(펀더멘털)이
  주가에 정보로 반영(가격을 강제하진 않음, 창발). 국가 생산(§경제 틱)이 회사
  투입/산출로 흐른다.
- **채권↔전쟁/재정**: 국채로 전쟁 자금 조달 → 이자 부담. 패전·재정파탄 시 디폴트.
- **ADR↔FX**: 예탁기관이 홈 주식을 잠그고 타 시장 통화로 ADR 발행. 홈가격×FX와
  ADR 시세의 괴리가 차익거래 기회. 예탁 재고 = 발행 ADR × ratio 불변식.

## 8. 공매도·파생 (확정: 포함)

MVP에 **공매도 + 파생(옵션·선물) 모두 포함**으로 확정(2026-08-03). 2DStock의
금융 깊이(공매도·옵션)를 계승하되, 유저 발행·서버 권위 위에서 재구성한다.

- **공매도**: 포지션이 음수로 갈 수 있음(`settleFill`의 `allowShort`). 단, 증거금
  필요(`MarginRequirement`) — 순자산 대비 유지증거금 미달 시 강제청산.
- **옵션**: `OptionDetails`(콜/풋·행사가·만기·계약규모·현물/현금결제). 발행자(라이터)는
  증거금 예치. 만기 틱에 자동 정산(worldTick 연동).
- **선물/무기한**: `FutureDetails`(만기·계약규모·개시/유지증거금률). 마크투마켓으로
  틱마다 손익 반영, 유지증거금 미달 시 청산.
- **정산 엔진은 다음 슬라이스.** 현재는 계약 스키마·증거금 불변식만 정의했다.
  마크투마켓·강제청산·행사/만기 정산은 원장 위에 별도 모듈로 구현(하프 구현 방지).

### 남은 세부(착수 전 확정)

1. **통화 다중성**: 국가별 통화 거래 시 FX·환전 시장 도입 시점.
2. **거래 수수료·세금**: 거래소 수수료(국가 수입)·양도세 도입 시점.
3. **증거금·청산 파라미터**: 개시/유지증거금률, 청산 페널티, 보험기금 여부.

## 9. MVP 수직 슬라이스(경제)

1. 유저가 회사 설립 → 주식 IPO(발행량·공모가).
2. 다른 유저가 매수 주문 → **호가장 매칭 → 정산**(구현된 코어 위에).
3. 발행자가 배당/증자 1종 실행.
4. ETF 1종 생성 → NAV 표시.
5. 국채 1종 발행 → 쿠폰 지급(worldTick 연동).
6. (확장) ADR로 타 시장 교차 상장 1건.

## 11. 가격의 단일성 — "모두가 같은 가격을 보는가?"

**그렇다. 단, 2DStock과 이유가 정반대다.**

- **2DStock**: 가격이 고정 기원점 결정론 *공식*이라 모든 클라이언트가 각자 계산해도
  같은 값 → 서버 불필요. 대신 실제 유저 거래가 가격에 영향을 못 준다.
- **CivilStock**: 가격은 실제 주문 흐름에서 창발하므로 클라이언트가 계산할 수 없다.
  대신 **서버(Cloud Run + Postgres)에 단일 권위 상태**(호가장·마지막 체결가·AMM
  준비금)가 있고, 모든 클라이언트가 그 하나를 구독해 읽는다 → 같은 가격.

즉 "같은 가격"은 **결정론이 아니라 단일 진실원본(single source of truth)**으로
보장된다. 이건 유저 상호작용을 위해 반드시 치러야 하는 구조 전환이다. 거래는
연속·실시간으로 이 상태를 갱신하고, worldTick은 그 위에서 시간종속 이벤트만 얹는다
(쿠폰·만기·NAV) — worldTick이 순간가격을 바꾸는 게 아니다.
