# CivilStock 경제 모듈 설계

> 목표: **유저가 직접 만드는 2DStock.** 유저는 시장 조성자(market maker)이자
> 시장 참여자로서 증시·실물경제·채권을 두루 컨트롤한다. 운영자는 **제재·삭제만**
> 하고, **주식·ETF 발행권은 유저에게 이양**한다. 국가 상장 주식을 ADR로 발행하는
> 등의 교차 상장 예외도 지원한다.

## 0. 2DStock과의 결정적 차이

| | 2DStock | CivilStock |
|---|---|---|
| 상장/발행 | 운영자가 종목 편성 | **유저가 발행**(주식·ETF·채권) |
| 가격 | 클라이언트 결정론 계산 | **유저 주문 흐름에서 창발**(서버 매칭) |
| 운영자 | 시장 설계자 | **제재·삭제만**(사기·조작 대응) |
| 실물경제 | 배경 시뮬 | 회사 실적·자원과 **직접 연동** |

가장 중요한 전환은 **가격 형성**이다. 유저가 시장 조성자가 되려면 가격이
결정론이어선 안 된다. 서버 권위형 매칭 엔진이 실제 매수/매도 주문을 체결하고,
그 체결에서 가격이 창발한다.

## 1. 행위자(actor)와 역할

- **유저**: 발행자(회사·ETF·채권) / 시장조성자(호가 게시·유동성 공급) /
  트레이더 / 펀드매니저 — 한 유저가 여러 역할을 겸한다.
- **국가**: 자국 통화 발행, 거래소 호스팅, 상장 규정 설정, 국채 발행. (국가는
  1인국 또는 멀티국이 운영 — §국가 설계와 연결.)
- **회사/ETF/채권**: 유저가 발행하는 상품.
- **운영자(admin)**: 제재·삭제만. 발행 게이트키핑 없음.

## 2. 상품(instrument) 분류

`src/lib/economy/types.ts`의 `SecurityType`.

1. **주식(equity)** — 유저 회사 지분. 발행자가 발행량·증자·자사주·분할·배당 통제.
2. **채권(bond)** — 국채/회사채. 원금·표면금리·만기·쿠폰주기. 발행자 파산 시 디폴트
   (전쟁 패배 국가의 국채 디폴트 등 §전쟁과 연결). 신용도는 창발.
3. **ETF(etf)** — 유저가 구성한 바스켓(주식·채권·다른 ETF·자원 편입 가능).
   생성/상환은 바스켓 대비. NAV는 구성종목 시세로 계산.
4. **ADR(adr)** — 홈 시장 상장 증권을 **다른 시장의 통화로 거래**하는 예탁증서.
   예탁기관(유저/기관)이 홈 주식을 보관하고 ADR을 발행·상환. ADR 1주 = 홈 주식
   `ratio`주. 시세는 자시장 주문 흐름에서 창발 → 홈가격×FX 대비 **차익거래**
   여지가 콘텐츠가 된다.
5. **통화(currency)** — 국가 통화(FX). 국가가 발행량 통제 → 인플레·환율.
6. **자원/재화(commodity)** — 실물경제 산출물. 회사의 투입/산출과 연동.

모든 상품은 공통 헤더(`Security`) + 종류별 detail 레코드로 구성. 매칭·정산 코어는
상품 종류에 무관하게 동작한다(어떤 상품이든 호가장 + 원장으로 거래).

## 3. 발행(issuance) — 발행권 이양의 핵심

- **회사 설립 → 주식 발행(IPO)**: 유저가 발행주식수·공모가·통화를 정해 상장.
  이후 증자(secondary), 자사주 매입, 액면분할, 배당을 발행자가 통제.
- **ETF 발행**: 구성종목·비중 정의 → 생성/상환.
- **채권 발행**: 원금·표면금리·만기 정의 → 시장에서 소화.
- **스팸/사기 방지(발행은 자유롭되)**:
  - 국가 거래소별 **상장 규정**(최소 자본·공시 의무)을 국가 운영 유저가 설정.
  - **평판/공시**: 발행자 신뢰도, 허위공시 페널티.
  - 운영자 **제재·삭제**: 명백한 사기·조작만 사후 개입.
  - 서버 **불변식**: 발행량 보존, 음수 잔고 금지(§정산).

## 4. 가격 형성 — 매칭 엔진 (구현 완료: 순수 코어)

- **가격-시간 우선(price-time priority) 지정가 호가장**. `matchOrder`가 들어온
  주문을 반대편 호가장(best-first)과 체결하고, **메이커(호가 게시자) 가격**으로
  체결가를 매긴다(테이커에 가격 개선).
- 부분체결·잔량 처리. 순수 함수라 서버·테스트에서 동일하게 동작.
- 파일: `src/lib/economy/orderBook.ts` (`matchOrder`, `sortRestingBook`).
- **열린 결정 — 유동성 모델(아래 §8)**: 순수 호가장(CLOB)만으로는 유저 발행
  마이크로캡의 호가가 텅 빌 수 있다. AMM(유동성 풀) 병용 여부가 큰 갈림길.

## 5. 정산(settlement) — 원장과 불변식 (구현 완료: 순수 코어)

- **현금 원장**(userId→통화→잔액) + **포지션 원장**(userId→증권→수량).
- `settleFill`: 체결 한 건을 매수자↔매도자 사이에 정산. **검증 통과 시에만** 반영:
  - 매수자 현금 ≥ 결제금액(부족 시 `insufficient_cash`).
  - 매도자 포지션 ≥ 수량(공매도 금지 MVP, 부족 시 `insufficient_position`).
- 서버 권위: 실제로는 Cloud Run 서버가 이 규칙대로 **Postgres 트랜잭션**에서
  원자적으로 수행. 이 모듈은 테스트 가능한 기준 구현.
- 파일: `src/lib/economy/ledger.ts`.

## 6. 큰 수 처리와의 결합

모든 금액·수량은 `src/lib/number/exactAmount.ts` 위에서만 연산한다.

- 현금: 통화별 **정수 최소단위 문자열**(ExactAmount). float 금지.
- 가격: "증권 1.0단위당 결제통화 최소단위" 정수 문자열.
- 수량: 최대 6자리 소수(micros) 문자열.
- 결제금액 = `exactPositionValue(price, qty)` — 천문학적 국부 규모에서도 손실 없음.
- 테스트가 2^53 초과 체결 정산을 검증(`scripts/test-economy.ts`).

## 7. 실물경제·채권·ADR 연동(설계)

- **실물경제↔증시**: 회사는 자원을 투입해 재화를 생산 → 매출·실적(펀더멘털)이
  주가에 정보로 반영(가격을 강제하진 않음, 창발). 국가 생산(§경제 틱)이 회사
  투입/산출로 흐른다.
- **채권↔전쟁/재정**: 국채로 전쟁 자금 조달 → 이자 부담. 패전·재정파탄 시 디폴트.
- **ADR↔FX**: 예탁기관이 홈 주식을 잠그고 타 시장 통화로 ADR 발행. 홈가격×FX와
  ADR 시세의 괴리가 차익거래 기회. 예탁 재고 = 발행 ADR × ratio 불변식.

## 8. 남은 결정 (경제 모듈 착수 전)

1. **유동성 모델**: (a) 순수 호가장(CLOB) / (b) CLOB + AMM 유동성 풀 병용 /
   (c) AMM 우선. 마이크로캡 유동성·시장조성 재미의 핵심 갈림길.
2. **공매도·레버리지·파생**: MVP에 포함? (2DStock엔 공매도·옵션 있었음.) 현재
   코어는 공매도 금지 기본.
3. **통화 다중성**: 국가별 통화로 거래 시 FX·환전 시장을 언제 도입?
4. **거래 수수료·세금**: 거래소 수수료(국가 수입)·양도세 도입 시점.

## 9. MVP 수직 슬라이스(경제)

1. 유저가 회사 설립 → 주식 IPO(발행량·공모가).
2. 다른 유저가 매수 주문 → **호가장 매칭 → 정산**(구현된 코어 위에).
3. 발행자가 배당/증자 1종 실행.
4. ETF 1종 생성 → NAV 표시.
5. 국채 1종 발행 → 쿠폰 지급(worldTick 연동).
6. (확장) ADR로 타 시장 교차 상장 1건.

## 10. 현재 구현 상태

- `src/lib/economy/types.ts` — 상품·주문·체결 도메인 타입.
- `src/lib/economy/orderBook.ts` — 가격-시간 우선 매칭(순수).
- `src/lib/economy/ledger.ts` — 현금·포지션 원장 + 정산 불변식(순수).
- `scripts/test-economy.ts` — 매칭·정산·큰 수 불변식 테스트(통과).
- 실행: `npm run test:economy`, 타입: `npm run typecheck`.
